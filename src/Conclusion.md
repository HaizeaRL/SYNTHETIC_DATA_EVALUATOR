## Conclusion

The generation of synthetic data using the `SDV library` was conducted following guidelines provided in both the [SDV paper](../resources/SDV.pdf) and the [SDV tutorial](https://docs.sdv.dev/).

**Note:** The evaluation of the synthetic data is available in the `4-sdv_synth_data_evaluator.ipynb` Jupyter notebook file, which provides a detailed analysis of the generated data.

Given the way the `SDV library` handles missing values, these values were removed entirely during preprocessing. This resulted in a refined original dataframe with 61,504 rows and 36 columns: 8 numeric and the rest categorical.

Two synthesizers from the `SDV library` were employed for synthetic data generation:
1. `GaussianCopula`
2. `CTGAN`

### GaussianCopula

During the synthetic data generation using the `GaussianCopula` synthesizer, several limitations were noted, as highlighted in a [discussion thread](https://github.com/sdv-dev/SDV/issues/310). Some categories had missing values, and in a few cases, certain categories were entirely absent. Additionally, the categorical data distributions were not preserved.

On the other hand, the generation of numeric values produced significantly more accurate results. By configuring the numeric distributions correctly, the synthetic results closely mirrored the real data.

To handle memory constraints, two separate synthesizers were used: one specifically for the two high-memory `gaussian_kde` numeric columns (`synth_kde`) and another for the remaining numeric and categorical data (`synth_full`). This approach allowed for efficient resource management while preserving data integrity.

Achieving results closer to the original with `GaussianCopula` requires additional post-processing to ensure that at least one instance per category is created and that distributions more closely match the real dataset.

### CTGAN

The `CTGAN` synthesizer was trained with a minimum of 300 epochs to balance time constraints with model learning efficiency. As training progressed, model performance improved, with generator loss stabilizing in a negative range, indicating realistic synthetic samples. However, the discriminator loss values showed significant oscillations, suggesting variability, although no signs of overfitting were observed.

The synthetic data generated by `CTGAN` suggests that additional training epochs or further adjustments are needed to produce results that more closely align with the real dataset.

### Mostly.AI

Creating synthetic data with `Mostly.AI` was significantly simpler. Only basic preprocessing was required, and the platform allowed the generation of synthetic data with distributions and correlations that closely match the original dataset—up to 99.1% similarity. Categorical distributions were maintained accurately.

In the results, some values were labeled as _RARE_ due to a mechanism in `Mostly.AI` that replaces infrequent categories with _RARE_ to ensure privacy. This is intended to prevent re-identification of rare individuals by omitting extremely infrequent values in the synthetic data.

In our case, if it is necessary to avoid missing values and represent all categories in the synthetic data, the generation process could be adjusted to include these rare categories explicitly. However, this feature requires a paid account.

### Summary

Data privacy is crucial, especially when sensitive information needs to be shared. Traditionally, anonymization methods were used to protect data, but with advancements in technology and Big Data, synthetic data generation using machine learning has become a prevalent solution.

Today, synthetic data can be generated through two primary methods: using open-source libraries like `SDV` or online platforms such as `Mostly.AI`. While `SDV` presents some limitations with categorical data and may require additional training or post-processing, `Mostly.AI` offers a more straightforward solution for generating highly realistic synthetic values efficiently, making it the preferable choice in this case.
